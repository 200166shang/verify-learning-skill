# Tensor：端侧模型实际处理的数据是什么

理解端侧模型部署时，首先要建立一个基本认识：**模型真正接收和输出的不是“图片”“一句话”这些业务概念，而是 Tensor。** 图片、音频、文本等业务数据，需要先转换成模型约定的 Tensor；模型完成计算以后得到的也仍然是 Tensor，之后再由后处理把这些数值解释成类别、坐标、概率等业务结果。

## Tensor 是什么

**Tensor（张量）是一种用于表示多维数组的数据结构，也是深度学习框架存储和计算模型数据的基本单位。** 一个 Tensor 由一组元素以及描述这些元素组织方式的属性共同构成，其中最常见的属性就是维度、`shape` 和 `dtype`。

从数据结构上看，Tensor 可以是 0 维、1 维、2 维乃至更高维的数组：

```text
0 维 Tensor：3.14

1 维 Tensor：[1, 2, 3]

2 维 Tensor：[[1, 2, 3],
             [4, 5, 6]]

3 维 Tensor：可以理解为多张二维矩阵继续沿新的方向堆叠
```

因此，“Tensor 就是一组数字”只是帮助建立直觉，更准确地说，**Tensor 是按照若干维度组织起来的数值数组**。模型中的输入数据、中间特征以及最终输出，通常都以 Tensor 的形式存在。

## Dimension：Tensor 有几个方向

**Dimension（维度，也常称 axis / 轴）表示 Tensor 需要使用多少个独立的索引，才能定位其中的一个元素。Tensor 有多少个轴，就称它是几维 Tensor。**

例如：

```text
[1, 2, 3]
```

只需要一个索引就可以定位元素，例如 `x[1]`，因此它是 1 维 Tensor。

而：

```text
[[1, 2, 3],
 [4, 5, 6]]
```

需要“第几行、第几列”两个索引，例如 `x[1][2]`，因此它是 2 维 Tensor。

这里的“维度”不要和某一维的“大小”混在一起。上面的矩阵有 **2 个维度**，但第 0 维大小为 2，第 1 维大小为 3。这些大小组合起来，才形成下面要说的 `shape`。

## Shape：每个维度分别有多大

**Shape（形状）是一个整数序列，用来描述 Tensor 在每一个维度上的元素数量。** 如果一个 Tensor 有 n 个维度，那么它的 shape 就包含 n 个整数。

例如：

```text
Tensor： [1, 2, 3]
Shape：  [3]
```

它只有一个维度，这个维度上有 3 个元素，所以 shape 是 `[3]`。

再看二维矩阵：

```text
[[1, 2, 3],
 [4, 5, 6]]
```

它有 2 行、3 列，因此：

```text
shape = [2, 3]
```

也就是说：

```text
维度数量：2
第 0 维大小：2
第 1 维大小：3
```

图像模型中经常看到：

```text
shape = [1, 3, 224, 224]
```

如果模型采用 NCHW 布局，这四个数字分别表示：

```text
1    → N，batch size，一次输入 1 个样本
3    → C，channel，3 个颜色通道
224  → H，height，图像高度
224  → W，width，图像宽度
```

因此这个 Tensor 一共有：

```text
1 × 3 × 224 × 224 = 150528
```

个元素。

这里还需要区分 **shape 和 layout**。Shape 只告诉我们每一维有多大，而 layout 描述这些维度按照什么语义顺序排列。例如 `[1, 3, 224, 224]` 常对应 NCHW，而 `[1, 224, 224, 3]` 常对应 NHWC。两者元素总数相同，但各个轴的业务含义和内存组织约定不同，所以部署代码必须按照模型要求组织输入。

对于序列模型，也可能看到：

```text
[batch, seq, hidden]
```

分别表示一次处理多少个样本、每个样本有多少个序列位置，以及每个位置使用多少维特征表示。业务含义虽然不同，但 Shape 的定义没有变化：**它始终是在描述 Tensor 每一个轴的大小。**

## Dtype：每个元素是什么数据类型

**Dtype（data type）表示 Tensor 中单个元素使用的数据类型，它决定元素的数值表示方式、精度范围以及单个元素通常需要的存储空间。**

常见类型包括：

```text
float32
float16
int8
uint8
int32
```

例如两个 Tensor 的 shape 都是 `[1, 3, 224, 224]`，并不意味着它们的数据表示完全相同：一个可能使用 `float32`，另一个可能使用 `int8`。前者通常使用浮点数表示模型输入或特征，后者则常见于量化模型。

因此部署时不仅要检查 shape，还必须检查 dtype。例如模型要求 `float32` 输入，而程序却直接把原始 `uint8` 图像 buffer 当作 `float32` Tensor 使用，即使宽、高、通道完全正确，模型读到的数值含义依然会错误。

## Batch：一次组织多少个样本

**Batch 表示一次模型计算中共同组织和处理的样本数量；在常见 Tensor 表示中，batch size 通常作为 shape 的一个维度存在。**

例如 NCHW 图像 Tensor：

```text
[1, 3, 224, 224]
```

第一个 `1` 表示一次处理 1 张图片；如果变成：

```text
[8, 3, 224, 224]
```

则表示一次组织 8 张相同规格的图片进行计算。

所以 Batch 不是另一种特殊数据结构，而是 Tensor 某个轴所表达的业务含义。训练阶段常通过较大的 batch 提高硬件并行利用率；端侧实时推理更关注单次响应延迟，因此经常看到 batch size 为 1。

## 把几个概念放在一起

现在可以用一个 Tensor 同时理解这些概念：

```text
Tensor shape = [1, 3, 224, 224]
dtype        = float32
layout       = NCHW
```

它表达的是：这是一个 **4 维 Tensor**；它的 **Shape 是 `[1, 3, 224, 224]`**；四个轴分别有 1、3、224、224 个元素；按照 NCHW 解释时，这些轴分别表示 Batch、Channel、Height、Width；其中每一个元素的数据类型都是 **float32**。

因此可以把关系记成：

```text
Tensor
├── 数据：真正保存的一组数值
├── Dimension：有多少个轴
├── Shape：每个轴分别有多大
├── Dtype：每个元素是什么数据类型
└── Layout：各个轴按照什么语义顺序组织

Batch
└── 通常是其中某个轴的业务含义
```

## Tensor 与端侧部署代码的关系

从部署视角看，可以把数据链路简化成：

```text
业务原始数据
    ↓
预处理
    ↓
Input Tensor
    ↓
模型推理
    ↓
Output Tensor
    ↓
后处理
    ↓
业务结果
```

因此以后阅读真实端侧部署模块时，如果看到代码在申请输入 buffer、查询 input shape、检查 dtype、调整 NCHW/NHWC、填充输入数据，本质上都可以归到同一个问题：**程序正在按照模型要求构造 Input Tensor。**

模型执行完成以后，Runtime 返回的 Output Tensor 同样具有自己的 shape 和 dtype。程序读取其中的数值并转换成业务语义，则进入后处理阶段。

## 内容小结

Tensor 是深度学习中表示和计算多维数据的基本数据结构；Dimension 表示 Tensor 有多少个轴；Shape 表示每个轴分别包含多少个元素；Dtype 表示每个元素的数据类型；Batch 表示一次共同处理多少个样本，并通常体现为 Tensor 的一个轴。

对于端侧部署来说，真正重要的是建立“Tensor 契约”的认识：**模型要求的不只是有一块输入数据，而是要求这块数据具有正确的 shape、dtype 和 layout。** 预处理负责把业务数据变成符合这个契约的 Input Tensor，模型计算得到 Output Tensor，再由后处理把这些数值解释成业务程序能够使用的结果。
