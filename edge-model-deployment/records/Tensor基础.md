# Tensor：端侧模型实际处理的数据是什么

理解端侧模型部署时，首先要建立一个最基本的认识：**模型真正接收和输出的不是“图片”“一句话”这些业务概念，而是 Tensor。** 图片、音频、文本等原始业务数据，需要先被转换成模型约定形状和数据类型的 Tensor，模型完成计算后得到的也仍然是 Tensor，之后再由后处理把这些数值解释成类别、坐标、概率等业务结果。

## Tensor 是什么

可以先把 Tensor 理解成“带有维度结构的一组数字”。一个数字可以看成 0 维 Tensor，一串数字可以看成 1 维 Tensor，一个矩阵可以看成 2 维 Tensor，而图像 Batch、序列特征等通常会继续增加维度。

因此，Tensor 最重要的不只是里面有哪些数字，还包括这些数字按照什么结构排列。阅读部署代码时，经常看到 `shape`、`dtype`、`batch` 等信息，它们实际上是在描述模型输入输出 Tensor 的数据契约。

## Shape 描述数据怎样排列

`shape` 表示 Tensor 每个维度的大小。例如图像模型中常见：

```text
[1, 3, 224, 224]
```

可以理解成：

```text
1    → 一次输入 1 张图片，也就是 batch
3    → 3 个通道
224  → 图像高度
224  → 图像宽度
```

所以这个 Tensor 中实际包含：

```text
1 × 3 × 224 × 224
```

个数值。

不同模型可能使用不同的维度顺序。例如 `[1, 3, 224, 224]` 和 `[1, 224, 224, 3]` 包含的元素数量可以完全一样，但每个维度代表的含义不同。因此部署代码不能只保证数据数量正确，还必须按照模型要求的 layout 组织 Tensor。

对于序列模型，也可能看到类似：

```text
[batch, seq, hidden]
```

这里分别表示一次处理多少个样本、每个样本包含多少个序列位置，以及每个位置使用多少维特征表示。具体业务不同，但理解方式相同：**shape 的每一维都对应数据结构中的一个含义。**

## Dtype 描述每个元素怎样存储

除了 shape，Tensor 还必须有数据类型，也就是 `dtype`。例如：

```text
float32
float16
int8
uint8
```

同样一个 shape，如果 dtype 不同，内存占用和数值表达方式都会不同。

例如模型要求 `float32` 输入，而程序却直接把 `uint8` 图像数据当作输入，即使宽高和通道数完全正确，模型看到的数值含义仍然可能是错误的。因此端侧部署中的预处理通常不仅负责 resize、归一化等业务转换，也负责最终把数据组织成模型真正要求的 shape 和 dtype。

## Batch 是 Shape 中的一个维度

`batch` 表示一次送入模型多少个样本。例如：

```text
[1, 3, 224, 224]
```

中的第一个 `1` 表示一次处理一张图片；如果是：

```text
[8, 3, 224, 224]
```

则表示一次组织 8 张同规格图片一起计算。

Batch 并不是“模型内部又多了一种特殊数据”，它本质上就是 Tensor 的一个维度，用来把多个相同结构的样本组织在一起。训练时经常通过较大的 batch 提高 GPU 并行利用率；端侧实时推理为了低延迟，则经常看到 batch 为 1。

## Tensor 与端侧部署代码的关系

从部署视角看，可以把数据链路先简化成：

```text
业务原始数据
    ↓
预处理
    ↓
Input Tensor
    ↓
模型推理
    ↓
Output Tensor
    ↓
后处理
    ↓
业务结果
```

因此以后阅读一个真实端侧部署模块时，如果看到代码在申请输入 buffer、查询 input shape、检查 dtype、调整通道顺序、填充输入数据，本质上都可以归到同一个问题：

> 程序正在把业务数据转换成模型能够接受的 Tensor。

模型执行完成以后，程序读取 output tensor，再把其中的数值转换成业务语义，则进入后处理阶段。

## 内容小结

Tensor 可以理解成模型世界中的统一数据表示：**数据内容是一组数值，shape 描述这些数值怎样组织，dtype 描述每个数值怎样存储，batch 通常是 shape 中表示一次处理多少个样本的维度。**

对于端侧部署来说，不需要先深入 Tensor 的数学理论，更重要的是看到一段部署代码时能够意识到：模型输入输出都有严格的 Tensor 契约，预处理负责把现实业务数据变成符合这个契约的 Input Tensor，模型计算得到 Output Tensor，再由后处理把它重新解释成业务能够使用的结果。
